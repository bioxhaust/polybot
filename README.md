# Polybot

Бумажный бот для крипто-рынков [Polymarket](https://polymarket.com): «биткоин или эфир выше, ниже или внутри диапазона к моменту экспирации». Реальных ордеров он не отправляет и ключи от кошелька не использует. Задача прогона — понять, есть ли преимущество у модели, а не заработать.

## Стратегия

На каждом цикле бот берёт живые данные:

- рынки и стаканы Polymarket;
- опционную цепочку Deribit и считает по ней вероятность исхода;
- спот Binance, потому что рынки Polymarket закрываются по нему, а не по индексу Deribit.

Если после проскальзывания в стакане вероятность модели выше цены Polymarket хотя бы на 3 цента, бот покупает этот исход виртуально и держит его до закрытия рынка. В последний час перед экспирацией новые сделки не открываются: опрос раз в 30 секунд там проигрывает ботам, которые смотрят Binance напрямую.

В коде есть ещё сканер полных наборов («Да» + «Нет» дешевле $1) и симулятор маркет-мейкинга. В запущенном цикле работает сигнальная стратегия; маркет-мейкинг в цикл не подключён.

## Запуск локально

Нужен [uv](https://docs.astral.sh/uv/) и Python 3.12+.

```bash
uv sync
cp .env.example .env
uv run python -m polybot
```

Остановка — Ctrl+C. База появляется в `data/polybot.sqlite`.

Отчёт по накопленным сделкам:

```bash
uv run python -m polybot report
```

Главная строка отчёта — `Verdict`. Она сравнивает точность модели (Brier score) с точностью цены Polymarket на одних и тех же закрытых рынках. Сумма бумажной прибыли на коротком отрезке этого не заменяет: несколько десятков сделок легко заканчиваются плюсом или минусом случайно.

## Настройки

Файл `.env`, шаблон — `.env.example`.

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `POLYBOT_BANKROLL_USD` | `10000` | Виртуальный банк |
| `POLYBOT_RISK_UNIT_PCT` | `0.005` | Риск на сделку, доля банка. При $10 000 это $50 |
| `POLYBOT_MIN_EDGE` | `0.03` | Минимальное преимущество после издержек |
| `POLYBOT_THEME_LIMIT_R` | `3` | Сколько сделок одновременно на один актив |
| `POLYBOT_DAILY_LOSS_LIMIT_R` | `1000` | Дневной стоп в единицах риска. 1000 на бумажном прогоне не срабатывает |
| `POLYBOT_WEEKLY_LOSS_LIMIT_R` | `7` | После −$350 за 7 дней размер сделки уменьшается вдвое |
| `POLYBOT_POLL_SECONDS` | `30` | Пауза между торговыми циклами |
| `POLYBOT_SNAPSHOT_SECONDS` | `300` | Как часто писать стаканы и вероятности в базу |
| `POLYBOT_MIN_TRADE_TTE_MINUTES` | `60` | Не входить за столько минут до экспирации |

Снимки раз в 5 минут занимают примерно 0.7 ГБ в день.

## Сервер

Юнит systemd лежит в `deploy/polybot.service`. Он рассчитан на каталог `/opt/polybot`, пользователя `polybot` и интерпретатор `.venv/bin/python`.

```bash
sudo cp deploy/polybot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now polybot
journalctl -u polybot -f
```

Состояние риска живёт в памяти процесса. После перезапуска лимиты считаются заново. Отчёт от этого не зависит: он пересчитывает сделки по базе.
