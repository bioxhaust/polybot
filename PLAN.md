# Polybot: план работ

Бот торгует **без денег** (paper trading) на крипто-рынках Polymarket (цена BTC/ETH выше/ниже/в диапазоне).
Цель первого этапа — выяснить, есть ли у нас преимущество, а не заработать.

Две стратегии на одной основе:

1. **Сигнальная.** Справедливая вероятность из опционов Deribit; покупаем, если рыночная цена
   после издержек отличается от справедливой больше порога.
2. **Маркет-мейкинг + мержи** (как у прибыльных кошельков chubbito/Lennie): лимитные заявки
   на YES и NO вокруг справедливой цены, пары YES+NO меняются на $1 мержем.

Плюс безрисковый сканер полных наборов (сумма цен всех исходов < $1).

## Правила для всех агентов

- Работай **только в своих файлах**. Общие типы — `src/polybot/models.py`. Менять их без
  крайней необходимости нельзя; если без этого никак — добавляй поля с дефолтами, не ломай
  существующие, и опиши изменение в итоговом сообщении.
- Сигнатуры функций в заглушках — это контракт. Реализуй их; дополнительные хелперы можно.
- Все `datetime` — timezone-aware UTC. Цены токенов — в [0, 1].
- Никаких приватных ключей, кошельков и отправки реальных ордеров.
- Сеть в тестах не используется: HTTP мокается через `respx`, данные — фикстуры в `tests/fixtures/`.
  Фикстуры снимай с реального API один раз и сохраняй как JSON.
- Перед завершением: `uv run pytest` и `uv run ruff check` проходят.

Запуск: `uv sync`, затем `uv run pytest`.

## Этап 0 — каркас ✅

Структура проекта, общие типы (`models.py`), конфиг (`config.py`), заглушки всех модулей.

## Этап 1 — параллельно

### A. Клиент Polymarket и парсер рынков
Файлы: `polymarket/client.py`, `polymarket/parser.py`, `tests/test_polymarket_*.py`.
- Gamma API: активные ценовые рынки BTC/ETH. CLOB API: стаканы по `token_id`, батчем.
- Парсер: актив, тип (ABOVE/BELOW/RANGE), страйки, **точное время экспирации в UTC**,
  источник цены из правил рынка, `event_id`, `neg_risk`.
- Рынки «достигнет ли цена X когда-нибудь» (path-dependent) — **не поддерживаем**, возвращаем None.
- Всё, что не распознано уверенно, — None. Тесты на 20+ реальных формулировках.

### B. Deribit и модель вероятности (самая важная задача)
Файлы: `deribit/client.py`, `deribit/pricing.py`, `tests/test_deribit_*.py`.
- Публичный API: опционная цепочка (`get_book_summary_by_currency`, kind=option), индекс.
- `prob_above`: риск-нейтральная \(P(S_T > K)\) = \(N(d_2)\) с поправкой на наклон улыбки
  волатильности (\(-\partial C/\partial K\) через численную производную по страйку).
- Интерполяция полной дисперсии \(\sigma^2 T\) по времени между соседними экспирациями;
  экспирации Deribit — 08:00 UTC.
- RANGE = разность двух `prob_above`. BELOW = 1 − ABOVE.
- Учти разницу между индексом Deribit и источником разрешения (Binance) — запиши её в `meta`.
- Тесты: монотонность по страйку, границы [0, 1], сверка с аналитикой Блэка–Шоулза на
  плоской улыбке, сумма вероятностей полного набора диапазонов ≈ 1.

### C. Издержки, полные наборы, paper broker
Файлы: `execution/costs.py`, `execution/complete_sets.py`, `execution/paper.py`, тесты.
- `estimate_fill`: проход по стакану, средняя цена, проскальзывание, комиссия.
- `edge_after_costs`, `max_size_for_edge`.
- Полные наборы: YES+NO одного рынка; YES всех взаимоисключающих диапазонов события
  (проверить `neg_risk`, одинаковую экспирацию, непрерывное покрытие без дыр).
- `PaperBroker`: исполнение рыночных ордеров только по реальному стакану, мерж, расчёт по исходу.

### D. Журнал (SQLite)
Файлы: `storage/journal.py`, `tests/test_journal.py`.
- Схема для всех типов из `models.py`, миграции (`PRAGMA user_version`).
- Снимки стаканов — на каждом тике по всем рынкам (это данные для бэктеста).
- Чтение для отчёта. Тест: запись → чтение даёт равные объекты.

### G. Анализатор кошельков (независимая)
Файлы: `polymarket/wallets.py`, `tests/test_wallets.py`.
- Data API: сделки кошелька и сделки по рынку.
- `compute_stats`: PnL, просадка, число дней, доля крипто-рынков, доля мейкерских сделок, мержи.
- Скрипт: найти кошельки, стабильно прибыльные на крипто-рынках (≥ 200 сделок, ≥ 30 дней).
  Для проверки — кошельки из статей: Lennie `0x0f1b8f81fdcb47b6c3292b8dbf6c2c16b3c4d367`.

## Этап 2 — после слияния A–D

### E. Риск-модуль и главный цикл
Файлы: `engine/risk.py`, `engine/loop.py`.
- Размер позиции от R (0.5% банка), с учётом того, что стоп может проскочить.
- Лимиты: −3R в день, −7R в неделю (после — размер вдвое), 3R на тему (актив),
  максимум 2 попытки на сетап, не больше 1% объёма рынка.
- Цикл: рынки → стаканы → Deribit → справедливая цена → сигналы и полные наборы → риск →
  paper broker → журнал. Перезапросы при ошибках API, корректный выход по Ctrl+C.

### F. Отчёт
Файл: `report.py`.
- Подтягивать исходы рынков, считать PnL виртуальных сделок.
- **Главная метрика:** Brier score модели против Brier score рыночной цены на одних и тех же
  моментах. Если модель не лучше рынка — преимущества нет.
- Калибровка по корзинам вероятностей, прибыль полных наборов.

## Этап 3 — после E и F

### H. Маркет-мейкинг (симулятор)
Файл: `execution/maker.py`.
- Котировки YES и NO вокруг справедливой цены (`yes_bid + no_bid < 1`), сдвиг против
  накопленной позиции, снятие заявок при резком движении спота.
- **Консервативное исполнение:** мы последние в очереди на своём уровне; исполнение только
  сделками, прошедшими через наш уровень (из публичных сделок), а не касанием цены.
- Сравнить наши котировки с поведением кошельков из задачи G.
- Результат симулятора считать оптимистичной оценкой: финальная проверка — только малыми
  реальными деньгами, отдельным решением.
